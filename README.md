# FocusSense

On-device attention and fatigue detection for remote software developers. A Flutter Android app that reads the front camera, runs Google ML Kit Face Mesh on the phone, and flags sustained low attention with a break suggestion. No video or landmark data ever leaves the device.

Built for IT6070 Emerging Topics in IT, Assignment II (SLIIT).

## Features

1. **Real-time attention and fatigue detection (Monitor tab).** ML Kit Face Mesh (468 landmarks) feeds an eye aspect ratio (EAR) and a head-yaw proxy. Each frame is classified as `focused`, `drowsy`, `distracted`, `uncertain` or `noFace`.
2. **Sustained low-attention detection and history (Dashboard tab).** A rolling-window aggregator watches the state stream. When low attention is sustained, it logs a highlighted "break suggested" entry. State changes are listed by day.
3. **Settings tab.** Adjust the EAR and yaw thresholds (saved on the device), review the privacy statement and clear the history.
4. **Onboarding.** Requests camera permission and states that no cloud API is used.

| Test device | Physical Android phone with a front camera, Android 5.0 (API 21) or later |

An emulator is not recommended: its virtual camera is unreliable for face detection.

Platform note: Google ML Kit Face Mesh Detection is Android-only (and Beta), so iOS, web and desktop are not supported.

## Installation and execution

This repository holds the app source (`lib/`, `test/`, `pubspec.yaml`) and the Android manifest additions. The Android project scaffolding is generated by Flutter.

```bash
# 1. Check the toolchain
flutter doctor

# 2. Create the base Android project
flutter create --platforms=android focussense_app
cd focussense_app

# 3. Copy this repository's files over the generated ones
#    - replace pubspec.yaml
#    - replace the lib/ and test/ folders
```

4. Open `android/app/src/main/AndroidManifest.xml` and merge in the `<uses-permission>` and `<uses-feature>` lines from this repository's `android/app/src/main/AndroidManifest.xml`, just above `<application>`. The key one is:

   ```xml
   <uses-permission android:name="android.permission.CAMERA" />
   ```

5. In `android/app/build.gradle` (or `build.gradle.kts`), make sure the minimum SDK is 21 or higher, for example `minSdk = 21` (older templates use `minSdkVersion 21`).

6. Install dependencies and run on the connected phone:

   ```bash
   flutter pub get
   flutter devices          # confirm the phone is listed
   flutter run              # debug run
   # or
   flutter build apk --release   # APK at build/app/outputs/flutter-apk/app-release.apk
   ```

7. Run the unit tests (aggregator logic):

   ```bash
   flutter test
   ```

### First launch

1. Read the privacy screen and tap the button to grant camera permission.
2. Open the **Monitor** tab and hold the phone steady (a stand works best) with your face in view.
3. Watch the **Dashboard** tab for logged state changes and break suggestions.

## Required API or configuration information

- **No API keys, accounts, servers or environment variables are needed.** All processing is on the device with free packages.
- **Permission:** `CAMERA`, requested at runtime on the onboarding screen.
- **Default detection settings** (changeable in the Settings tab, stored with `shared_preferences`):

  | Setting | Default |
  | --- | --- |
  | Eye-closure threshold (EAR) | 0.21 |
  | Head-turn threshold (yaw) | 30 degrees |

- **Aggregator constants** (in `lib/services/attention_aggregator.dart`):

  | Constant | Value |
  | --- | --- |
  | Rolling window | 5 minutes |
  | Sustained duration | 3 minutes |
  | Sustained fraction | 70% of the window |
  | Cooldown between break suggestions | 10 minutes |

- **Main dependencies:** `camera`, `google_mlkit_face_mesh_detection`, `permission_handler`, `shared_preferences`, `provider`, `intl`, `google_fonts`. See `pubspec.yaml` for versions.
- `google_fonts` downloads fonts at runtime unless they are bundled, so the first launch may need a network connection for typography only. Nothing about the camera or detection uses the network.

## Known limitations

- **Android only.** ML Kit Face Mesh has no iOS, web or desktop support, and the API is in Beta.
- **Heuristic, not a trained model.** States come from fixed EAR and yaw thresholds, which need per-user calibration in Settings. Different faces, glasses and lighting can shift the right values.
- **Yaw is a 2D proxy** (nose tip against the face edges), not a full 3D pose estimate.
- **Single face assumed.** Multiple faces in view can give wrong results.
- **Lighting and camera angle** affect accuracy and can cause false positives or negatives. Low light or the phone placed off-axis is the usual cause.
- **Battery use.** Continuous camera and inference drain the battery. Keep the phone on a charger for long sessions.
- **Foreground only.** The camera pipeline runs while the app is open on screen. There are no push notifications or background service; break suggestions appear only as Dashboard entries.
- **Limited testing so far.** The aggregator has unit tests, but the full app has had only limited on-device testing. Treat the results as a proof of concept, not a clinical or safety tool.
- **History is local.** Logged entries live on the device only and are lost if app data is cleared.

## Project structure

```
lib/
  main.dart                      app entry, theme, routing
  models/attention_state.dart    state enum and log entry model
  services/
    face_mesh_service.dart       camera frames to ML Kit landmarks
    attention_classifier.dart    EAR and yaw to per-frame state
    attention_aggregator.dart    rolling window, sustained-low detection
    attention_controller.dart    shared state for the tabs
    preferences_service.dart     saved thresholds and onboarding flag
  screens/                       onboarding, main (bottom nav), monitor, dashboard, settings
  widgets/attention_timeline.dart
  theme/app_theme.dart
test/attention_aggregator_test.dart
```

## Privacy

Camera frames are processed in memory and discarded. Only the attention state and a timestamp are logged, and nothing is transmitted.
